# v1.1.1 Bug Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the issues found after v1.1.0 so a v1.1.1 patch release can ship.

**Architecture:** Small, local fixes in the notification core (internal/notify), its producers (internal/docker, internal/pkg, internal/brew, internal/integrations), and the web app (service worker registration, notifications panel, settings card). No new features, no schema changes.

**Tech Stack:** Go, React + TanStack Query, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-12-notifications-design.md` and `docs/superpowers/specs/2026-11-12-service-worker-design.md` (behaviour these fixes restore). Already done on this branch: 44a7cb7 (leaner Transmission polling).

## Global Constraints

- Branch `v1.1.1`, local commits only; never push.
- Each fix: failing test first (watch it fail), then the fix; tests named per task.
- No new dependencies; gofmt; Prettier `--print-width 140` only on files you create; edit existing files by hand.
- No em or en dashes as punctuation in code, copy or docs. Commit messages plain English, no AI attribution.
- Full check before each task's commit: `go vet ./... && go test ./... && GOOS=linux go vet ./...`, and for web tasks `cd web && npm test && npx tsc -b && npm run build`.

## Review Focus

- A download that starts and finishes within one 10 s poll after Wargo has been running: exactly one "finished" push (Task 1 `TestFinishBetweenPolls`).
- Two desktop tabs open, a new version deployed, the second tab opened: the first visible tab must not reload (Task 4 `shouldReloadOnControllerChange` tests).
- A failed manual check then a restart: no re-push of known updates (Task 2 `TestStartupSkipsFailedCheck`).
- Image checks failing intermittently: no repeat "updates found" push for the same image (Task 3 `TestFailedImageCarriesForward`, Task 1 `TestUpdatesNotifiedSetRemembered`).
- A torrent removed and re-added with the same hash: a fresh started/finished cycle (Task 1 `TestReaddedTorrentNotifiesAgain`).

### Task 1: Notification core

**Files:** `internal/notify/active.go`, `internal/notify/updates.go`, tests in `internal/notify/active_test.go`, `internal/notify/updates_test.go`.

- **Fast finish:** a non-baseline SetDownloads that sees a hash for the first time already complete (Percent >= 1, seeding or done), when that hash was not in the baseline, raises `download.finished` (and pushes per mode). Test `TestFinishBetweenPolls`; also a hash present at baseline as complete stays silent.
- **Prune and re-add:** after a successful (non-error) SetDownloads, delete from `l.dls` every hash missing from the list, so a re-added hash starts fresh. Test `TestReaddedTorrentNotifiesAgain` (started push, finished push, removed, re-added: started and finished push again).
- **Checking/queued keep their row:** a hash already showing in Active (seen downloading) keeps its Active row while its status is `checking` or `queued` (only stopped, seeding/done or removal take it out). Test `TestCheckingKeepsActiveRow`.
- **Empty Plex session key:** a Stream with an empty SessionKey gets a synthetic key from user + rating key (or player) so sessions do not collapse into one row. Test `TestEmptySessionKeysStaySeparate`.
- **Disk unmounted:** every ReportDisks call with a non-empty list resolves open `disk.full` items whose mount is missing (Reconcile on every call, keeping the 85 percent band for mounts still present). Test `TestUnmountedDiskResolves`.
- **Updates re-push:** remember the names already notified per source (pushed or seen in a manual check) instead of comparing only with the previous report, so {a,b} then {b} then {a,b} does not push `a` again; a source's notified set is trimmed to its current names only when a report succeeds and the name has been absent for 7 days (or simply never trimmed within a process; your call, document it). Test `TestUpdatesNotifiedSetRemembered`.
- [ ] Tests first (RED), fix, full check (GREEN), commit "Notify fast and re-added downloads and keep notified updates".

### Task 2: Startup baseline after a failed check

### Task 3: Docker producer

**Files:** `internal/docker/notify.go`, `internal/docker/service.go` (event plumbing if needed), `internal/docker/notify_test.go`.

- **Rename:** handle the `rename` event: resolve open items keyed by `Attributes["oldName"]` (both categories), then track the new name (the next sync or health event raises it if still unhealthy/failed). Test `TestRenameMovesProblem`.
- **Wording:** `container.failed` titles: "<name> stopped with an error" for a die with a bad exit, "<name> keeps restarting" when the state is restarting; resolved titles unchanged. Update tests that assert the old text.
- **STOPSIGNAL:** treat the container's configured stop signal (from inspect `Config.StopSignal`, by number or name) as terminating too, cached per container; fall back to 9/15/2/3. Test `TestCustomStopSignalIsStop`.
- **Flaky image checks:** when an image's check failed this round (`updateAvailable == nil` with an error), keep its name in the reported container update names if it was reported before, so a transient failure does not drop it. Test `TestFailedImageCarriesForward`.
- [ ] Tests first, fix, full check, commit "Track renamed containers and describe container failures accurately".
